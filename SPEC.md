## 1. Elevator Pitch

Learn a fast graph-based (or CNN-based) surrogate that predicts transient temperature fields in a battery module under varying loads and cooling boundary conditions, replacing expensive finite-difference PDE solvers with a neural network that is 100-1000× faster while maintaining physical consistency through physics-informed training.

## 2. Physical System and Physics

### System Description
- **Domain**: 2D cross-section of a battery pack containing multiple cells and cooling channels
- **Geometry**: Regular Cartesian grid (64×64 or 128×128) with three material regions:
  - Battery cells (0): Generate heat, moderate thermal conductivity
  - Coolant channels (1): High heat capacity, good conductivity
  - Insulation (2): Low conductivity, outer boundary

### Governing Equations

**Heat equation** with internal heat generation:

```
ρ(x,y) · cp(x,y) · ∂T/∂t = ∇ · (k(x,y) · ∇T) + q(x,y,t)
```

**Boundary conditions** (Robin/convective):

```
-k · ∂T/∂n = h · (T - T_amb)
```

Where:
- T(x, y, t): Temperature [K]
- ρ(x, y): Density [kg/m³], spatially varying by material
- cp(x, y): Specific heat capacity [J/(kg·K)], spatially varying
- k(x, y): Thermal conductivity [W/(m·K)], spatially varying
- q(x, y, t): Volumetric heat generation [W/m³], non-zero only in battery cells
- h: Convective heat transfer coefficient [W/(m²·K)]
- T_amb: Ambient temperature [K], typically 298.15 K

### Discretization

**Spatial**: Second-order central differences on uniform grid with spacing dx = dy = 1 mm

**Temporal**: Explicit forward Euler with CFL-stable time step:
```
dt ≤ (ρ·cp) / (2·k) · (dx²·dy²) / (dx² + dy²)
```

Typically dt ≈ 0.5-2 ms for stability.

## 3. Exact ML Task

### Task Type
**Surrogate Modeling**: Learn the one-step time evolution operator T_{t+Δt} = F(T_t, params)

### Input and Output

**Input** (9 channels, shape: B × 9 × H × W):
1. Temperature field at time t, T(x, y, t) [K]
2. Material mask: battery cell (binary)
3. Material mask: coolant (binary)
4. Material mask: insulation (binary)
5. Thermal conductivity field k(x, y) [W/(m·K)]
6. Volumetric heat generation q(x, y) [W/m³]
7. Convection coefficient h [W/(m²·K)]
8. Signed distance field to cell boundary [grid cells]
9. Signed distance field to coolant boundary [grid cells]

**Output** (1 channel, shape: B × 1 × H × W):
- Predicted temperature field at time t + Δt, T(x, y, t+Δt) [K]

### Prediction Modes
- **One-step**: Direct prediction of next time step (primary mode)
- **Multi-step rollout**: Iterative application for longer trajectories (evaluation mode)

## 4. Data

### 4.1 Data Source
**Synthetic data** generated by a finite-difference heat equation solver implemented in `src/physics/solver.py`.

### 4.2 Data Generation

**Domain**:
- Grid: 64×64 (MVP) or 128×128 (high-fidelity)
- Spatial resolution: dx = dy = 0.001 m (1 mm)
- Domain extent: 64 mm × 64 mm or 128 mm × 128 mm
- Time interval: t ∈ [0, 1.0] s with dt ≈ 0.001 s

**Parameters** (sampled uniformly per trajectory):

| Parameter | Symbol | Range | Units |
|-----------|--------|-------|-------|
| Cell thermal conductivity | k_cell | [0.5, 5.0] | W/(m·K) |
| Heat generation rate | q₀ | [1e5, 5e6] | W/m³ |
| Convection coefficient | h | [10, 500] | W/(m²·K) |
| Oscillation frequency | f | [0.5, 5.0] | Hz |

**Fixed material properties**:
- Battery cell: ρ=2500 kg/m³, cp=700 J/(kg·K)
- Coolant (water): k=0.6 W/(m·K), ρ=998 kg/m³, cp=4182 J/(kg·K)
- Coolant (air): k=0.026 W/(m·K), ρ=1.225 kg/m³, cp=1006 J/(kg·K)
- Insulation: k=0.04 W/(m·K), ρ=30 kg/m³, cp=1400 J/(kg·K)

**Samples**:
- MVP: 200 trajectories × 100 time steps = ~20,000 training pairs
- Full: 2000 trajectories × 200 time steps = ~400,000 training pairs

**Initial conditions**: Uniform temperature T₀ = 298.15 K (ambient)

**Time-varying heat source**: q(t) = q₀ · (1 + 0.5 · sin(2πft)) for load cycling

**Optional noise**: Gaussian noise σ=0.5 K added to temperature measurements

### 4.3 Data Format

**Storage**: HDF5 file with gzip compression (level 4)

**Structure**:
```
thermal_dataset.h5
├── temperature:  (n_traj, n_steps, H, W)  float32, ~500 MB - 5 GB
├── parameters:   (n_traj, 4)              float32  [k_cell, q₀, h, f]
├── mask:         (H, W)                   int8     [0, 1, 2]
├── sdf_cell:     (H, W)                   float32
├── sdf_coolant:  (H, W)                   float32
└── attributes:   {grid_size, dx, dy, dt, n_steps, T_amb, ρ, cp}
```

**Training example construction**:
- Each trajectory contributes (n_steps - 1) input-target pairs
- Inputs are constructed on-the-fly in `ThermalDataset.__getitem__()`
- No preprocessing or normalization required (data already in physical units)

## 5. Model and Physics Usage

### 5.1 Architecture

**Primary Model: Physics-Conditioned U-Net (PC-U-Net)**

- **Type**: Encoder-decoder with skip connections
- **Levels**: 4 (base_features=32, doubles at each level)
- **Input channels**: 9
- **Output channels**: 1
- **Normalization**: GroupNorm (8 groups when possible)
- **Activation**: GELU
- **Dropout**: 2D spatial dropout (p=0.1) for MC uncertainty
- **Physics conditioning**: MLP projects global physics vector (k_mean, q_mean, h_mean) to spatial biases at each encoder/decoder level

**Baseline Model: SimpleCNN**

- **Type**: Residual convolutional network
- **Layers**: 8 residual blocks
- **Hidden channels**: 64
- **No physics conditioning** (for ablation study)

**Stretch Goal: GNN**

- **Implementation**: Pure PyTorch (no PyG dependency)
- **Graph construction**: 4-connected grid (using networkx for edge list generation)
- **Node features**: Same 9 channels as CNN input
- **Message passing**: 3-5 layers of graph convolution
- **Output**: Per-node temperature prediction

### 5.2 Physics Usage

**Physics-Informed Loss** (3 active phases):

**Phase 1 (epochs 1-50): Data-only pretraining**
```
L = λ_data · MSE(T_pred, T_target)
```
- λ_data = 1.0
- Goal: Learn basic temperature evolution patterns

**Phase 2 (epochs 51-150): Physics-informed training**
```
L = λ_data · L_data + λ_pde · L_pde + λ_bc · L_bc
```
- λ_data = 1.0, λ_pde = 0.1, λ_bc = 0.1
- L_pde: PDE residual ||ρ·cp·∂T/∂t - k·∇²T - q||²
- L_bc: Robin BC violation at boundaries
- Goal: Enforce physical consistency

**Phase 3 (epochs 151-200): Consistency fine-tuning**
```
L = λ_data · L_data + λ_pde · L_pde + λ_bc · L_bc + λ_cons · L_consistency
```
- λ_cons = 0.05
- L_consistency: Multi-step prediction error (2-step vs ground truth)
- Goal: Stabilize long-term predictions

**Adaptive loss balancing** (optional):
- GradNorm algorithm dynamically adjusts {λ_data, λ_pde, λ_bc, λ_cons}
- Prevents any single loss term from dominating
- α = 1.5 for slight emphasis on data loss

### 5.3 Training Details

**Optimizer**: AdamW
- Learning rate: 1e-3
- Weight decay: 1e-5
- Gradient clipping: max_norm = 1.0

**Scheduler**: CosineAnnealingLR
- T_max = 200 epochs
- η_min = 1e-6

**Batch size**: 16 (GPU) or 8 (CPU)

**Mixed precision**: Enabled on CUDA only (not MPS/CPU due to compatibility)

**Early stopping**: Patience = 20 epochs on validation loss

**Data splits**:
- Train: 70% of trajectories
- Validation: 15%
- Test: 15%
- Split by trajectory ID to avoid data leakage

## 6. Evaluation

### 6.1 Metrics

**Primary**:
- **Relative L2 error**: ||T_pred - T_true||₂ / ||T_true||₂
- **MAE**: Mean absolute error [K]
- **RMSE**: Root mean squared error [K]
- **Max error**: max|T_pred - T_true| [K]
- **Peak cell temperature error**: Error on maximum T in battery cells

**Secondary**:
- Inference time [ms per forward pass]
- Speedup vs finite-difference solver
- Uncertainty calibration (for MC Dropout)

### 6.2 Baselines

1. **Pure Data-Driven CNN**: SimpleCNN trained only with MSE loss (no physics)
2. **Linear Interpolation**: Trivial baseline (T_{t+1} ≈ T_t)
3. **Finite-Difference Solver**: Ground truth (but slow)

### 6.3 Main Experiments

**Experiment 1: Baseline Comparison**
- Compare PC-U-Net (physics-informed) vs SimpleCNN (data-only)
- Expected: 20-50% error reduction with physics

**Experiment 2: Generalization to Unseen Parameters**
- Train on k ∈ [0.5, 5.0], q ∈ [1e5, 5e6]
- Test on out-of-distribution cases:
  - k_cell = 0.3 (below training range)
  - q₀ = 6e6 (above training range)
  - h = 5 (weak cooling, rare in training)
- Metric: Relative L2 error, stability over 20-step rollout

**Experiment 3: Multi-Step Rollout Stability**
- Autoregressive prediction: T_{t+k} = F(F(...F(T_t)))
- Rollout length: 50-100 steps (0.05-0.1 s)
- Metric: Cumulative error, divergence time

**Experiment 4: Uncertainty Quantification**
- Use MC Dropout (N=20 forward passes)
- Compute prediction mean and standard deviation
- Metric: Calibration plot (predicted uncertainty vs actual error)

**Experiment 5: Computational Speedup**
- Benchmark FD solver (NumPy) vs surrogate (PyTorch)
- Devices: CPU (laptop), GPU (Colab T4)
- Expected: 100-500× speedup on CPU, 500-1000× on GPU

### 6.4 Visualizations

- Side-by-side temperature field comparison (true vs predicted)
- Spatial error maps
- Training curves (train/val loss over epochs)
- Multi-step rollout snapshots
- Uncertainty heatmaps (MC Dropout std)

## 7. Novelty

### Scientific Contributions

1. **Hybrid Physics-Data Approach**: Combines data-driven learning with explicit PDE residual enforcement for battery thermal systems (not just toy 1D examples)

2. **Multi-Material Surrogate**: Handles spatially varying material properties (cells, coolant, insulation) via:
   - Material masks (one-hot encoding)
   - Property fields (k, ρ, cp as input channels)
   - Signed distance fields (geometric information)

3. **Practical System**: Realistic battery pack geometry, time-varying heat loads (discharge cycles), and convective cooling boundaries

4. **Uncertainty Quantification**: MC Dropout provides epistemic uncertainty estimates for safety-critical applications

5. **Cross-Platform Implementation**: Pure PyTorch + NumPy (no OS-specific dependencies), works on macOS/Windows/Linux/Colab

### Technical Innovations

- **Physics conditioning blocks**: Inject global physics parameters (k, q, h) as spatial biases at each U-Net level
- **3-phase training curriculum**: Gradual introduction of physics constraints prevents mode collapse
- **Adaptive loss balancing**: GradNorm ensures stable multi-objective optimization
- **Differentiable PDE operators**: All spatial derivatives and Laplacians implemented as PyTorch operations for end-to-end gradient flow
